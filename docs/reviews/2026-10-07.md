## Reproduksi dan perubahan

1. Bulk menerima `bulan=2026-99` dengan HTTP 200, bukan error validasi. Kedua endpoint kini memvalidasi format `Y-m`; JSON invalid memperoleh 422 tanpa penulisan.
2. Pada tanggal uji 31 Oktober, bulk Februari membuat periode **1 Maret**. Parser `!Y-m` menetapkan tanggal pertama sehingga tidak membawa tanggal sistem ke bulan pendek.
3. Preview bulk memuat sewa aktif yang belum mulai atau checkout tepat hari pertama bulan. Preview dan submit kini memakai filter overlap yang sama: mulai sebelum bulan berikutnya, checkout setelah awal bulan atau kosong. Status tetap aktif sesuai kebijakan sebelumnya; menunggak/selesai tidak dimasukkan.
4. PUT pembayaran lunas menerima perubahan Rp1 juta menjadi Rp1 dan tetap lunas, melewati approval ulang. Update dan delete kini mengambil lock pembayaran serta memeriksa status terbaru sebelum menulis atau menyentuh unggahan. Transaksi lunas ditolak dengan validasi; nominal pembayaran dan invoice tetap utuh. Form menjelaskan kunci dan menyembunyikan Simpan. Belum tersedia reversal/refund.

Peningkatan operasional: **tagihan massal pilihan**. Operator dapat menunda sewa tertentu tanpa kehilangan bulk untuk sewa lain. Kriteria penerimaan: hanya ID yang dipilih dibuat; tidak memilih apa pun (termasuk key checkbox hilang pada form HTML) ditolak; ID duplikat/tidak ditemukan/tidak berlaku ditolak; pilihan yang berubah ditolak atomik; pengulangan melewati tagihan pada bulan sama; izin create diperlukan. API lama tanpa parameter pilihan tetap membuat semua sewa yang memenuhi syarat. Batch mencakup pembayaran dan observer invoice dalam satu transaksi; sewa dikunci berurutan sebelum pemeriksaan duplikasi.

- Suite HTTP dalam framework tetap mencakup 18 halaman, kontrak PDF dan alur pendaftaran → pembayaran → approval → invoice.
- HTTP sungguhan server PHP lokal: login + CSRF/session; preview dua sewa sintetis; pilih satu → hanya satu dibuat; retry → nol tambahan; halaman sewa, pembayaran, invoice, keuangan dan dua laporan memberi respons berhasil. Percobaan server awal tidak terjangkau antar sesi alat; server dan klien dalam satu proses pengujian berhasil.
- Seluruh migrasi pada SQLite baru terpisah lulus, route cache dan view cache lulus; tidak ada migrasi baru dalam perubahan.
- `composer validate --strict`, `check-platform-reqs`, `audit --locked`: lulus, tanpa advisori. Dependency lokal dari lock baseline; fresh install akan diuji ulang CI PR.
- Empat tes frontend dan Vite build lulus. Peringatan fontaine opsional tidak memblokir build. Tidak ada tes visual browser/mobile baru.
- Tidak memakai data operasional, mengubah server/database produksi atau mengirim notifikasi penghuni. HTTP eksternal dicegah dalam tes baru.

## Batasan dan pekerjaan berikutnya

**Belum siap untuk operasional penuh.** Cakupan perubahan di atas lulus lokal; periksa hasil CI PR sebelum merge.

1. Invariant deduplikasi lintas manual, bulk dan link multi-bulan belum diselesaikan. Lock sewa menserialisasi sesama bulk pada database dengan row locking, tetapi writer manual/link belum mengikuti protokol ini. Uji concurrency pada jenis database deployment masih diperlukan; SQLite tidak membuktikan row locks.
2. Observer invoice masih mencari penghuni+tanggal, bukan identitas pembayaran/sewa. Dua sewa penghuni pada periode sama dapat berbagi invoice. Penghapusan pembayaran belum lunas masih dapat meninggalkan invoice. Perlu hubungan eksplisit serta rencana rekonsiliasi historis yang tidak menimpa invoice manual.
3. Approval tidak otomatis masuk buku Keuangan; kebutuhan pembukuan/reversal perlu implementasi terpisah dengan provenance dan deduplikasi.
4. Penggantian unggahan pembayaran belum lunas masih menghapus berkas lama sebelum database update selesai. Perlu lifecycle berkas pascacommit dan pembersihan berkas baru bila gagal; tidak dinyatakan aman oleh transaksi database saja.
5. Konfigurasi staging, locking DB deployment, mobile, backup dan integrasi layanan notifikasi masih perlu diverifikasi secara terpisah.

Kelanjutan harus membaca main/PR terbaru; jangan menggandakan branch yang belum merge.
