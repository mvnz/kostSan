# Update sewa setelah perpindahan kamar

## Kebutuhan dan kriteria sebelum menulis kode aplikasi

17 Oktober 2026 22.05 WIB: fetch main/default main tetap `3b23279a6e8cd0c3a1b655e1e472fe004a59b596`; head PR #10 `5a27a639736e3cdbdb538ba4237706d0bb6ad461`, CI39039370608 sukses. PR #4–10 draft, tanpa issue/komentar baru; worktree bersih, AGENTS.md tidak ditemukan. Checkpoint PR #10 menunjuk race update sebagai dugaan belum direproduksi, bukan bug yang sudah diperbaiki. Tidak mengulang perbaikan destroy.

Source update mengunci kamar binding dan kamar tujuan, lalu me-refresh sewa; kamar aktual setelah perpindahan lain bisa berada di luar kedua lock, tetapi tetap di-sync sesudah write. Dugaan: urutan sewa→kamar aktual dapat deadlock dengan checkout kamar→sewa. Manfaat: update yang tidak memegang semua lock sumber ditolak sebelum mutasi, dengan pemulihan jelas, tanpa melarang perpindahan sah.

Penerimaan: bind A pada worker, pause via pipe; controller parent benar-benar memindahkan A→B, lalu menahan lock B; lanjutkan request lama A→C. Source awal harus direproduksi gagal (deadlock atau perubahan tanpa proteksi), bukan hanya diperiksa string. Setelah fix worker harus menolak sebelum menyentuh B, lease/proof/nominal tidak berubah, checkout B dapat selesai tanpa deadlock. SQLite menguji penolakan, no-file-write dan fresh retry; kasus kamar aktual sudah sama dengan tujuan tetap diizinkan karena kamar itu sudah terkunci. Jangan mengubah aturan bisnis/histori/nominal, permission, migrasi, dependency atau lock order. MySQL CI sintetis terisolasi membuktikan row locks; SQLite/storage fake bukan bukti concurrency/storage deployment. PR terpisah dari #10; checkpoint final memuat self-review, tujuh kategori dan batas staging/UAT.

## Reproduksi dan fix

Tes sebelum fix: `1f4b2421402b9f91d732798325c1adefb386a8d6`, tree `e9c82e59f50c32d75c5444eb32b1eaf55f72259f`, [CI39043648113](https://github.com/mvnz/kostSan/actions/runs/39043648113). MySQL sesudah `CONTENTION stale edit/checkout` gagal DeadlockException SQLSTATE40001/1213 pada SELECT sewas FOR UPDATE oleh checkout. Dua proses nyata/controller asli, binding lama dibuat sebelum perpindahan controller lain; barrier pipe mengatur jeda binding, processlist membuktikan UPDATE kamar menunggu. Bukan salinan transaksi atau sleep yang dianggap bukti race. SQLite2 tes/9 assertion awal: satu gagal karena request lama masih memindahkan sewa lewat kamar tidak terkunci; kasus aman kamar aktual=tujuan sudah lulus. Browser awal dilewati karena backend merah, bukan hasil responsive.

Fix: setelah fresh lock sewa, pastikan kamar aktual terdapat di koleksi kamar yang sudah dikunci; jika tidak, ValidationException sewa meminta muat ulang sebelum availability/upload/write. Kamar aktual=tujuan tetap diizinkan. Tidak menambah lock terlambat, retry otomatis, atau larangan perpindahan kamar. Lokal: tes terkait23/163, suite204/1520, frontend11/build/UI check, Composer audit tanpa advisory/npm0 vulnerability. README menjelaskan pemeriksaan data terbaru dan retry. Hasil CI sesudah fix menunggu, tidak disamakan dengan hasil lokal.

Self-review eksplisit: tiga baris aplikasi memanfaatkan koleksi lock existing tanpa query/N+1 baru, urutan lock kamar ber-ID terurut→sewa tetap. Guard sebelum upload mencegah berkas pengganti/yatim, bukti lama dan cleanup afterCommit tetap. Permission/middleware, histori reservasi/pembayaran, tanggal/null date/nominal decimal, migrasi up/down, lifecycle pembayaran/invoice/ledger tidak diubah. Existing suite file atomicity, histori dan viewer403 dijalankan. Pesan muncul lewat error summary ber-role alert existing, bukan HTML baru. Test storage fake hanya membuktikan alur file, bukan ACL/disk failure produksi. Helper moveLease khusus harness dipakai worker dan parent memanggil controller asli dengan data sintetis; pipe hanya jeda antara binding dan controller, batas waktu worker25 detik/poll15 detik dan finally menutup input/rollback/menghentikan worker. Test tidak mengarang sukses checkout bila exception, tidak mengendurkan assertion, dan tidak mengklaim semua stale form/deadlock selesai.

UAT manusia belum tersedia. Skenario staging sintetis: admin memindahkan A→B ketika request operator A→C belum masuk transaksi; pesan muat ulang harus jelas, tidak ada bukti/nominal/status berubah dari request ditolak. Periksa data terbaru lalu ulangi jika masih diperlukan; C terisi/B tersedia setelah retry. Ulangi dengan actual B=tujuan B (tetap boleh), viewer tanpa hak update (403), konflik reservasi, dan checkout B bersamaan. Verifikasi engine/isolation/storage deployment dan kemudahan pemulihan; jangan menghubungi penghuni atau memakai data nyata.

Perintah lokal: `. ../php-env.sh`, `PAO_DISABLE=1 php vendor/bin/phpunit --fail-on-warning --fail-on-risky`, `--filter StaleLeaseUpdateTest`, `npm test`, `npm run build`, `php artisan kost:check-ui --no-interaction`, `php ../composer.phar audit --locked`, `npm audit --audit-level=low`. MySQL `php tests/Concurrency/mysql.php` hanya pada schema CI baru yang lolos target guard; Playwright `npm run test:browser` di CI. Jangan menjalankan migrasi fault injection pada produksi.
