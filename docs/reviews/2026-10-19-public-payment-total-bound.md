## Reproduksi dan implementasi

Source test-only `78244e2656eed466735027e3f6c488605896cf40`, tree `74b04233399f4224176d36471df1c884cb971b5c`. Lokal3tes/10assertion,2gagal: HTTP422 diharapkan tetapi200 diterima untuk tarif5000000000×3 dan tarif9999999999.99×1 yang dibulatkan ke10000000000. Link existing valid sudah lulus sebelum fix. [CI39257603481](https://github.com/mvnz/kostSan/actions/runs/39257603481) mereproduksi MySQL8.4.11 REPEATABLE-READ SQLSTATE22003/1264 Out of range jumlah pada controller public full-term aktual. Browser skipped karena backend merah, bukan lulus. Tidak mengklaim round-case MySQL red terpisah: harness berhenti pada multiply-case pertama; keduanya red pada HTTP SQLite.

Fix5baris setelah calculateBilling hanya di cabang pembayaran baru: hasil setelah pembulatan melebihi kapasitas ditolak sebelum file/create/token update, pesan metode meminta pengelola memeriksa tarif/masa sewa. Cabang existing payment di atasnya tidak diubah. Satu judul alert lama diganti agar benar untuk error pemrosesan, bukan selalu menyebut data belum lengkap; tidak menambah paragraf UI statis. README memuat pemulihan. Lokal tiga tes/48assertion lulus setelah guard, tanpa mengubah assertion atau formula. MySQL dan browser masih menunggu CI perbaikan.

Fixture browser menambah tiga lease/link sintetis (satu per viewport) di database guarded yang kosong. Token fixture dikenal hanya di lingkungan itu; bukan secret/tautan penghuni. Browser menguji penolakan/retensi keterangan, layout pesan, operator memperbaiki tarif melalui form edit nyata lalu link sama dapat dikirim. URL edit dibaca dari link tabel dan dinavigasi langsung; bukan bukti semua kontrol tabel mobile dapat diklik. PHPUnit/MySQL menguji token satu kali/nominal/coverage/approval, bukan browser yang diasumsikan menggantikannya.

Self-review eksplisit: kebutuhan setiap baris dibatasi kapasitas hasil hitung dan pemulihan. Tidak ada max tarif baru, clipping, otomatis mengubah data, dependency, perubahan lock ordering/transaksi/FK/migrasi, permission/CSRF atau notifikasi. Guard memakai hasil aktual sesudah tier/durasi/pembulatan, bukan input hidden jumlah yang tidak dipercaya. HTTP snapshots dan MySQL raw data/file/transaction checks mempertahankan histori saat error; existing bill tetap presisi9999999999.99. Blade meng-escape pesan. Tidak menambah query/N+1 atau file lifecycle baru. Kolom harga dan generator lain tetap belum diaudit menyeluruh; jangan menyatakan seluruh batas nominal/domain sudah selesai.
