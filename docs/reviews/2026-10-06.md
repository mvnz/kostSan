## Batasan dan prioritas berikutnya

**Belum siap untuk operasional penuh.** Kelulusan di atas berlaku untuk cakupan yang diuji, bukan sertifikasi seluruh modul.

1. Periksa model tagihan end-to-end: pembayaran manual/bulk/link belum memiliki invariant deduplikasi bersama. Link menghitung total masa sewa sedangkan bulk membuat tagihan bulanan; perlu memastikan tagihan yang sama tidak dibuat dua kali tanpa menghapus data lama.
2. Verifikasi invoice dan buku keuangan: sinkronisasi invoice mencari penghuni+tanggal periode, bukan identitas pembayaran/sewa, sehingga dua sewa penghuni dapat saling memengaruhi. Approval belum otomatis mencatat pemasukan pada Keuangan. Bedakan kebutuhan pembukuan manual dan otomatis, lalu tambahkan hubungan dan rekonsiliasi yang menjaga transaksi historis.
3. Uji locking dan request bersamaan pada jenis database deployment, termasuk benturan pindah kamar/approval. SQLite lokal tidak membuktikan perilaku row lock MySQL/PostgreSQL.
4. Uji penanganan kegagalan upload/database dan file yatim; tanggal selesai aktual serta perhitungan laporan hunian historis; input bulan pada bulk/laporan; perlindungan token link dalam log aktivitas; otorisasi detail lintas menu. Ini kandidat review berikut, belum diklaim aman hanya dari pembacaan kode.
5. Verifikasi staging dengan konfigurasi operasional: HTTPS, akun admin lama, storage, backup, format harga dan kebijakan pembulatan, tampilan mobile, PDF laporan, serta integrasi notifikasi melalui sandbox layanan. Jangan kirim pesan/invoice ke penghuni asli.

Lanjutkan dari main terbaru dan PR ini. Hindari menambahkan implementasi duplikat bila PR belum merge. Tidak ada migrasi baru atau backfill data pada perubahan hari ini.
