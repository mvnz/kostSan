## Perubahan dan self-review

Baseline lokal source basis: conversion6/43 assertion lulus, harness tidak memiliki skenario conversion. Sesudah tambahan: conversion7/55, seluruh backend205/1532, frontend11 lulus. Ini bukti tambahan terhadap perilaku yang sudah benar, bukan perbaikan aplikasi baru. MySQL/browser belum dinyatakan lulus sebelum hasil CI tersedia. README memberi petunjuk melihat sewa tertaut dan memeriksa status sebelum retry, bukan membuat sewa/ledger duplikat.

Self-review eksplisit: delta hanya tes/dokumentasi. Worker memanggil controller asli; old cancel bind sebelum lock kamar teramati di processlist, kemudian menunggu parent commit, sehingga fresh guard benar-benar diuji. Dua conversion worker masing-masing proses/koneksi dan kedua blocked query teramati, bukan retry berurutan. Snapshot raw diambil setelah fresh dari DB agar representasi decimal/datetime konsisten. Cek kegagalan write kedua ada di catch SEBELUM DROP CHECK (DDL MySQL dapat implicit commit); flag created membuktikan lease sempat ditulis, tidak hanya mengasumsikan rollback. Constraint dibatasi ID fixture dan dibuang melalui finally, tidak memakai SUPER/disable FK atau schema produksi. Retry memeriksa satu link/sewa dan tidak ada invoice/ledger tak diharapkan. Billing/approval dilakukan eksplisit setelah konversi sukses; uang jaminan/uang muka fixture bukan aturan baru auto-pemasukan. Tidak ada migrasi/up-down, dependency, izin, transaksi aplikasi, file lifecycle atau UI yang diubah. Guard kosong/null tanggal dan kasus konflik/tamper/ulang/histori serta private-file/role lama tetap dari suite existing; bukan klaim semua failure mode/engine/isolasi tercakup.

Perintah: `. ../php-env.sh`, `PAO_DISABLE=1 php vendor/bin/phpunit --filter ReservationConversionTest`, full `--fail-on-warning --fail-on-risky`; `npm test`, `npm run build`, `php artisan kost:check-ui --no-interaction`, `php ../composer.phar audit --locked`, `npm audit --audit-level=low`. CI menjalankan `php tests/Concurrency/mysql.php` pada target guarded baru,43 migrasi up/down/up, route/view cache dan `npm run test:browser`. Tidak jalankan harness pada DB operasional.

UAT manusia belum tersedia. Skenario sintetis staging: dua operator menekan simpan konversi reservasi sama; yang ditolak dapat membuka sewa tertaut tanpa membuat sewa baru. Operator yang sedang membatalkan mendapat penolakan setelah konversi selesai dan histori tidak berubah. Pada gangguan write penutupan reservasi, periksa status/tautan dan tidak adanya sewa yatim, perbaiki gangguan, retry satu kali, lalu tagih/approve dan cocokkan invoice/buku keuangan. Viewer tetap tidak bisa mengubah/menghapus. Verifikasi kemudahan pemulihan dan konfigurasi engine/isolation/storage deployment, bukan UAT otomatis atau data/pesan penghuni nyata.
